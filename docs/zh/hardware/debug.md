# 矩阵调试支持 {#sec:xsai-debug}

香炉峰（XSAI）没有为矩阵扩展增加专用的调试硬件，矩阵指令沿用昆明湖 V2R2 的调试机制（见基线手册「调试」章）。本章说明矩阵指令在调试时与普通指令有哪些不同，以及差分验证和 checkpoint 对矩阵状态的支持范围。

## 矩阵指令的提交与完成

理解矩阵调试，先要分清矩阵指令的两个时刻：

| 时刻 | 发生的事 |
| --- | --- |
| 提交 | 指令在核内流水线中完成全部检查并按序提交。此后它不会再产生异常 |
| 完成 | 矩阵单元实际执行完计算或访存。完成时间晚于提交，且不确定 |

核在指令提交后才把操作发给矩阵单元，矩阵单元异步执行。因此，当处理器停在某条指令处时，矩阵单元可能还在执行此前已经提交的操作。这是正常行为，不是错误。

## 断点与单步

断点和单步对矩阵指令的行为与普通指令相同，不需要特殊处理。原因是矩阵指令的异常判定全部在提交前完成，与普通指令走同一套机制。

## 查看矩阵寄存器

由于矩阵单元异步执行，断点停下的位置并不代表之前的矩阵操作已经完成。要查看某个操作写入的结果，先用 `macquire` 等待该操作完成，再读矩阵寄存器。不要根据断点位置推断结果已经写入。

## 错误报告

| 错误来源 | 表现 |
| --- | --- |
| 矩阵访存的地址翻译错误（page fault / access fault） | 在核内流水线中产生，是精确异常，可以正常调试 |
| 矩阵单元执行过程中的错误 | 矩阵单元不产生异常或中断，也不向核报告错误 |

因此，结果错误不会触发任何异常。排查时先排除程序本身的问题：读取未写入的矩阵寄存器区域、缺少同步、访存越界。

## 差分验证 {#sec:matrix-difftest}

差分验证在每条指令提交后，把 RTL 的状态与参考模型逐项比对。对矩阵扩展，比对范围包括：

* 矩阵 CSR：`mcsr`、`mxrm`、`msat`、`mfflags`、`mfrm`、`msaten`、`tlenb`、`trlenb`、`alenb`、`mtilem`、`mtilen`、`mtilek`、`msync`；
* 配置寄存器 `mcfg0` – `mcfg7`。

参考模型可以在 CPU 或 GPU 上运行。使用方法见[差分验证](../verification/difftest.md#sec:debug-difftest)。

## Checkpoint

**Checkpoint 不保存矩阵寄存器和矩阵 CSR。** 从 checkpoint 恢复后，矩阵状态不会还原，因此采样点必须选在没有矩阵操作进行、且后续不依赖此前矩阵寄存器内容的位置。

在负载中标记采样区间可以使用 `DISABLE_TIME_INTR`、`NOTIFY_PROFILER`、`NOTIFY_PROFILE_EXIT`。完整的切片与恢复流程见 [Checkpoint 与切片](../verification/checkpoint.md#sec:debug-checkpoint)。
