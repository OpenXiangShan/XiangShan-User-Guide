# 已知限制 {#sec:known-limitations}

本页列出当前版本确定的行为边界。这些不是待修的缺陷，而是使用前必须知道的约束；踩到边界时不会报错，只会算错或变慢。

## 内存

* **矩阵操作数缓冲必须物理连续**。行寻址按 `PA_base + row × stride` 计算且不逐行重查 TLB，非连续缓冲在行数较大时会静默读错。分配与池布局见[内存子系统与 HBL2](hardware/memory.md#sec:xsai-memory)。
* **池基址由运行期解析，不是固定地址**。环境变量 → 设备树 → 编译期默认值，先命中者胜。写死地址会在换了布局之后失效。
* **矩阵数据当前仍按一致性方案处理**。弱一致性方案尚在实现中，不要按弱一致性设计。
* **L2 的替换与预取尚未改进**。512 B/cycle 是命中场景的数字，未命中时实际带宽低于此值。

## 精度

* **`mcfg` 类型表里有当前不可用的类型**。int4、fp16、tf32、mxfp4、nvfp4 等列在表中，但矩阵单元没有块缩放数据路径，不能用于矩阵乘加。取用前用 `mgetcfg` 读回确认，见[指令集扩展](isa/instruction-set.md#sec:xsai-instruction-set)。
* **低精度转换指令本版未交付**。方向已定，但当前 SDK 不提供定义，不要按已有规格使用。

## 同步与内存序

* **`mrelease` / `macquire` 没覆盖所有退出分支会偶发算错**，且不会稳定复现。
* **基址寄存器被编译器回收同样表现为偶发错**。MSC 基址需钉在 `s11` 并保活到 `macquire`。

## 调试与采样

* **checkpoint 不保存矩阵寄存器堆与矩阵 CSR**。恢复清单里只有 `mstatus.MS` 位随 `mstatus` 恢复，因此矩阵切片分析的采样点必须处于静止态。
* **矩阵单元不产生也不回传异常**。没有矩阵专属的异常寄存器或 `mtval` 约定，异常全部在核内流水线的提交前判定，见[矩阵异常与中断](isa/exception.md#sec:xsai-exception)。

## 仿真

* **QEMU 只验算术语义**，不覆盖硬件的尺寸与布局约束（tile 尺寸、物理连续池、行寻址）。QEMU 全对不能推出板上正确，结论必须标注"仅算术结论"并以板上复验为准。
* **两个流程的 timebase 不是同一个值**。RTL 用核内 DTS（1 MHz），`firmware/nemu_board/dts/build/xiangshan_ai.dtb` 由 DTSGen 为固件流程生成（默认 10 MHz），DTB 不能在两条流程间直接搬运。
* **`make run-user` 不是通用验证入口**。它是本地便利目标，含硬编码模型路径。
