# 矩阵异常与中断 {#sec:xsai-exception}

本章描述矩阵扩展新增的异常与中断行为。通用 RISC-V 异常机制见基线手册；本章只覆盖矩阵指令与普通指令的差异。读本章前需要读过[指令集扩展](instruction-set.md#sec:xsai-instruction-set)与[矩阵 CSR](csr.md#sec:xsai-csr)。

## 异常种类

**只有三类矩阵指令会产生异常**：

| 指令类别 | 指令 | 可能产生的异常 |
| --- | --- | --- |
| 配置 | `msetcfg` / `mgetcfg` | 非法指令 |
| 矩阵乘加 | `mmacc` | 非法指令 |
| 矩阵访存 | 矩阵 load / store | 非法指令 + 访存异常（page fault / access fault 等） |

以下指令在硬件上不产生任何异常：`msettilem/n/k`（及其立即数形式）、`mzero`、`mrelease`。

### 非法指令的判定条件

**`msetcfg`**：`table_sel != 0`，或 `type_code` 不在合法类型表中。

**`mmacc`**：以下任一成立即为非法——

- 目的 / 源矩阵寄存器号非法（`md`、`ms1`、`ms2` 的最高位越界）；
- 某个操作数的 `mcfg` 项不受支持；
- 类型三元组不在受支持组合表内；
- `mtilem` 或 `mtilen` 超过 `ROWNUM`，`mtilek` 超过 A 类型的元素上限，`mtilen` 超过 C 类型的元素上限。

**矩阵访存**：寄存器号非法，或（非 whole-register 形式下）tile 维度超限。whole-register 形式不受 tile 维度检查。访存类异常来自 TLB（page fault / guest page fault / access fault）与 PMP 检查。

### 未对齐异常当前不产生

矩阵访存当前不产生未对齐异常——地址对齐检查被硬编码为始终通过，并标注有待实现。不要按"会产生未对齐异常"设计软件。

## 异常是精确的

矩阵异常满足精确异常定义：

1. 异常在写回时随异常向量写入 ROB 表项，而不是异步上报；
2. ROB 只在异常指令成为队头时统一触发陷入与重定向；
3. 异常指令自身被冲刷、不提交。

因此陷入前所有更老指令已提交、所有更年轻指令被丢弃，`mepc` 精确指向陷入指令。

### 异步执行如何与异常隔离

矩阵指令的写回是零延迟的架构事件，真正的计算和访存副作用只在提交之后才送往矩阵单元。由此得到三条结论：

- **被异常或冲刷丢弃的矩阵指令永远不会到达矩阵单元**——它们在提交之前已被丢弃；
- 异常路径生成的写回会显式阻止矩阵单元派发；
- 矩阵操作按程序序发出，不会出现"完成顺序 ≠ 程序顺序"引起的异常歧义。

一句话：**异常不在异步侧处理**。所有异常判定都在核内流水线中、提交之前完成，异步侧只执行已提交且已验证合法的操作。

### 矩阵单元内部不产生异常

矩阵单元没有任何异常、中断或陷阱端口。核与矩阵单元之间没有错误或撤销通道。

### 重放

只有矩阵 load / store 指令有重放，配有独立的矩阵访存重放队列。计算类矩阵指令（`mmacc`、`mzero`、`msettilex`、`mrelease`）没有重放。

### 序列化指令

以下指令是序列化的，不可被推测越过：

| 指令 | 行为 |
| --- | --- |
| `msetcfg` | 禁止推测执行 + 阻塞后续发射 + 提交时冲刷流水线 |
| `minit` | 禁止推测执行 + 阻塞后续发射 |
| `msyncregreset` | 禁止推测执行 |
| `macquire` | 禁止推测执行 + 阻塞后续发射 |
| `mfence` | 禁止推测执行 + 阻塞后续发射 |

`msetcfg` 提交时触发一次流水线重定向，保证矩阵配置变更不被推测越过。

## 异常寄存器内容

矩阵异常没有专属的异常寄存器字段，走通用路径：

- 矩阵写回与 CSR、load / store、向量等写回共用同一套异常合并机制；
- `mepc` / `mcause` / `mtval` 等内容全部来自陷入指令自己的 ROB 表项，没有矩阵专属字段；
- 矩阵访存的 TLB 异常复用通用 tval 通路。

矩阵异常的编码与寄存器内容约定 = 通用 RISC-V 约定 + 上表的异常类别，无需为矩阵定义新的异常编码。

矩阵专属的 `mtval` 内容约定，以及矩阵访存 `hardwareError` 的具体产生条件，在当前版本的 RTL 与材料中均未找到依据。

## 异常路径下的状态清理

矩阵推测状态的清理没有专属规则，沿用通用机制：

| 状态 | 清理方式 |
| --- | --- |
| 矩阵寄存器重命名 | 与整数 / 浮点 / 向量同构：快照回滚或按架构态 walk 重建 |
| MCFG（`msetcfg` 结果） | 分架构态与推测态；推测态在重定向后从架构态重建 |
| 非法 `msetcfg` | 被门控，不更新架构 MCFG 状态 |
| 矩阵访存队列 | 按 ROB 序号取消并回滚指针 |

**不存在"撤销矩阵副作用"的机制**：原因也简单——指令只在提交后才下发，未提交的指令根本不产生副作用，因此无需撤销。

未提交的一切推测状态按通用机制丢弃；已提交的矩阵副作用不可撤销、也不需要撤销。

## 中断

矩阵性能计数器的溢出中断 `LCOFIP` 采用中断向量号 13（12 已被 `SGEI` 占用）。它只由 HPM 计数器溢出产生，与矩阵单元没有专线，但矩阵性能事件已并入后端事件池，因此矩阵活动可以间接触发。详见[性能监测](../hardware/pmu.md#sec:xsai-pmu)。

矩阵状态本身没有专属中断，中断编号表中没有任何矩阵条目。

## `MS` 状态域

`mstatus.MS` 位于 **bit `[26:25]`**，复位值为 `Off`，编码为：`Off = 0`、`Initial = 1`、`Clean = 2`、`Dirty = 3`。`mstatus.SD`（bit 63）在 `FS` / `VS` / `MS` 任一为 `Dirty` 时读为 1。

**不存在 `msstatus` 寄存器**：矩阵状态只以 `mstatus.MS`（以及虚模式下的 `vsstatus.MS`）形式存在，`sstatus` / `vsstatus` 是别名通路。

### `MS = Off` 的实际效果

`MS = Off` 时访问 `mcsr`、`mxrm`、`msat`、`mfflags`、`mfrm`、`msaten` 这六个 CSR 会抛非法指令异常。

但要注意一处**尚未对齐的实现分歧**：

- 内核侧补丁实现了 **first-use trap**（建模自向量扩展的同类机制）：当 `MS = Off` 时执行矩阵指令，内核期望收到非法指令异常，然后在 handler 里把 `MS` 置为 `Initial` 并重试；
- 但 RTL 中解码侧的相关检查**目前全部被注释**，因此**当前 RTL 不会在解码期因此抛非法指令**。

也就是说：**规范与内核期待这道检查，RTL 尚未启用它**。在两者对齐之前，不要依赖"`MS = Off` 时矩阵指令会陷入"这一行为，也不要依赖"一定不会陷入"。以你所用 RTL 修订的实际行为为准，并在跨版本时重新确认。

另一处边界：**非虚模式下 `mstatus.MS` 不会被硬件自动置 `Dirty`**——该逻辑在 RTL 中被注释，只有虚模式下的 `vsstatus.MS` 分支生效。因此非虚模式下只能由软件显式写 `mstatus` / `sstatus` 来设置。

置脏的指令集为：写矩阵的 `mla` / `mlc` / `mzero` / `mmacc`；只读的 `msa` / `msc` **不置脏**。

### `MS` 翻转会冲刷流水线

`mstatus`、`sstatus`（别名）或 `vsstatus` 中 `MS` 在 `Off` 与非 `Off` 之间翻转时，会触发流水线冲刷。这是矩阵上下文状态切换的一致性保证点。

## 与 checkpoint / restore 的状态一致性

**当前 checkpoint / restore 链路不覆盖矩阵状态**，这是必须明确的已知限制：

| 项 | 是否被 checkpoint / restore 覆盖 |
| --- | --- |
| 矩阵寄存器堆（`tr0` – `tr3`、`acc0` – `acc3`） | **否**——checkpoint 载荷中没有对应段 |
| 矩阵 CSR（`mcsr` 及其余配置位） | **否**——恢复固件的恢复清单不含任何矩阵 CSR |
| `mstatus.MS` 位 | **是**——随 `mstatus` 一起恢复 |
| `mtilem` / `mtilen` / `mtilek` / `msync` | **否** |

向量寄存器有专门的镜像段，矩阵寄存器堆没有对应的任何一方。这是当前实现的一处不对称缺口。

由此推出的实践要求：

- **采样点必须使矩阵单元处于静止态**。已提交但尚未在矩阵单元中完成的操作若在恢复侧丢失，会造成架构不可见的状态发散；
- 需要显式同步时使用 `macquire` / `mrelease` / `msyncregreset` token 机制；
- 恢复后不要假设 `mxrm` / `mfrm` / `msaten` / `msat` / `mfflags` 与采样点一致；
- 涉及矩阵的切片分析应把"矩阵状态不随 checkpoint 恢复"作为已知前提写进结论。

## 信号常量

checkpoint 相关的仿真信号常量定义在 `firmware/LibCheckpoint/include/gcpt_trap.h`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `GOOD_TRAP` | `0x0` | 正常结束，通常也是 RTL 仿真终点 |
| `DISABLE_TIME_INTR` | `0x100` | 关闭定时器中断 |
| `NOTIFY_PROFILER` | `0x101` | 标记分析区间起点 |
| `NOTIFY_PROFILE_EXIT` | `0x102` | 标记分析区间终点 |

这些信号经 `nemu_signal` 用 `opcode 0x6B` 的自定义指令传参，不经过任何中断或异常机制，属仿真器专用旁路。详见 [Checkpoint 与切片](../verification/checkpoint.md#sec:debug-checkpoint)。
