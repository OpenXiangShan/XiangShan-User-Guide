# 差分验证 {#sec:debug-difftest}

差分验证把香炉峰的执行结果与参考模型逐条指令比对，是矩阵扩展功能正确性的主要手段。这一章讲参考模型能判断什么、不能判断什么，以及出问题时怎么用。

## 参考模型

| 参考模型 | 作用 |
| --- | --- |
| CPU 参考模型 | 默认路径 |
| GPU 参考模型 | 与 CPU 路径并行使用，可排除参考侧自身的实现差异 |

矩阵指令的比对支持批量传输、反压与顺序检查。

参考模型会把这些情况判为错误，而不是静默通过：读取从未写入的矩阵寄存器区域、缺少 `mfence`、`macquire` 之前访存越界。

## 矩阵寄存器的比对方式

早期实现把矩阵寄存器逐元素传输后比较，通信量很大。现在分两种：

| 指令类型 | 比对方式 | 原因 |
| --- | --- | --- |
| 结果唯一的运算（`mzero`、算术类） | 两侧各自算哈希后比较 | 通信量小；输入相同则哈希必然相同 |
| 有误差容忍的乘法类（`mma`） | 逐元素比较 | 结果不唯一，哈希不适用 |

## 怎么用

1. 日常验证默认开启差分（`make run-emu` 的 `DIFF` 默认为 1）；
2. 出现 mismatch 时，先关掉差分（`DIFF=0`）跑一遍，区分是差分接口本身的问题，还是 RTL 或参考模型的问题；
3. 参考模型与 DUT 必须使用**相同配置**，配置不同会产生系统性误报。

矩阵故障的常见现象与处理见[常见故障排查](troubleshooting.md#sec:debug-troubleshooting)。
