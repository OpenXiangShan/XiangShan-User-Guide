# Known Limitations {#sec:known-limitations}

This page lists the behaviour boundaries of the current release. They are not
defects waiting to be fixed but constraints you need to know before use: crossing
them raises no error, it just computes wrong results or runs slower.

## Memory

* **Matrix operand buffers must be physically contiguous.** Row addressing is
  `PA_base + row × stride` and does not walk the TLB per row, so a non-contiguous
  buffer is silently misread once the row count grows. Allocation and pool layout
  are in [Memory Subsystem and HBL2](hardware/memory.md#sec:xsai-memory).
* **The pool base address is resolved at run time, not fixed.** Environment
  variable, then device tree, then the compile-time fallback — first match wins.
  Hard-coding an address breaks as soon as the layout changes.
* **Matrix data is still handled coherently.** The weakly-consistent scheme is
  still being implemented; do not design against it yet.
* **L2 replacement and prefetch are not yet improved.** 512 B/cycle is the
  hit-path figure; effective bandwidth with misses is lower.

## Precision

* **Some types in the `mcfg` type table are not usable.** int4, fp16, tf32, mxfp4
  and nvfp4 are listed, but the matrix unit has no block-scaling data path, so they
  cannot be used for matrix multiply-accumulate. Read back with `mgetcfg` before
  relying on a type; see [Instruction Set Extensions](isa/instruction-set.md#sec:xsai-instruction-set).
* **The low-precision conversion instructions do not ship in this release.** The
  direction is settled, but the current SDK does not define them; do not use them
  as if the specification were final.

## Synchronization and memory ordering

* **`mrelease` / `macquire` not covering all exit branches makes results wrong
  intermittently**, and not reproducibly so.
* **The base register being reclaimed by the compiler shows up the same way.**
  Pin the MSC base to `s11` and keep it alive until `macquire`.

## Debug and sampling

* **A checkpoint does not save the matrix register file or the matrix CSRs.** The
  restore list carries only the `mstatus.MS` bit along with `mstatus`, so sampling
  points for matrix slice analysis must be taken while the unit is quiescent.
* **The matrix unit neither raises nor reports exceptions.** There is no
  matrix-specific exception register or `mtval` convention; all exceptions are
  decided in the core pipeline before commit. See
  [Matrix Exceptions and Interrupts](isa/exception.md#sec:xsai-exception).

## Simulation

* **QEMU verifies arithmetic semantics only** and does not cover the hardware's
  geometric constraints (tile shape, physically contiguous pool, row addressing).
  Passing in QEMU does not imply correct on hardware; label QEMU conclusions as
  "arithmetic criteria only" and re-verify on hardware.
* **The timebase is not one value across the two flows.** RTL uses the
  core-generated DTS (1 MHz), while `firmware/nemu_board/dts/build/xiangshan_ai.dtb`
  is generated by DTSGen for the firmware flow (10 MHz by default). A DTB must not
  be carried between the two flows.
* **`make run-user` is not a general verification entry point.** It is a local
  convenience target with a hard-coded model path.

## Relation to the baseline manual

This manual documents only the delta over Kunminghu V2R2. Anything not listed here
is identical to the baseline; the _XiangShan Open-Source Processor User Guide_ is
authoritative for it.
